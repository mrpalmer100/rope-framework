# NAME REGISTRY -- canonical symbols and the collisions they retire

Established 2026-08-13 (v3.24.5, the T4 ride-along session),
discharging the kappa/w/g rename sweep queued since PRED-003-ETA.
PURPOSE: prevent the next FND-066-class collision (a claim reading
"the SAME unregistered width w" when two registered objects wore the
name). CONVENTION: registered claim text is HISTORY and is NOT
rewritten by this sweep; the registry governs all NEW text (claims,
bars, results, docs, papers). When an older claim's bare symbol is
quoted, the quoting text must attach the canonical name in brackets.

## THE KAPPA FAMILY (four live objects, one label)

- kappa_lock -- the LOCKING MODULUS [J/m^2] (the elastic object of
  the locking sector). Bare "kappa" in locking-sector claims means
  this.
- kappa_grav -- the gravity sector's SURFACE GRAVITY [1/s or m/s^2
  per convention of the quoting claim]. Never write bare kappa in a
  gravity-sector context again.
- kappa_C -- ELEC-021's COULOMB COEFFICIENT [J m]. The electric
  sector's object.
- kappa_pack -- the PACKING/FLOOR PARAMETER of the bundle hierarchy
  (dimensionless; the kappa50 / kappa250 floors are its two
  registered values and keep their compact labels). This is the most
  used variant (80+ appearances) and is already unambiguous; no
  change.
- Derived/local variants in registered text (kappa_0, kappa_rel,
  kappa_c, kappa_fund, kappa_tw, ...) belong to their defining claims
  and are read there; none collides with the four above.
